## 追加 3：正解是开 pgdoc 插件，不用销毁重建（20:45）

- **上一轮「销毁重建文档型环境」的建议作废**。之前判断错在：以为文档库只能靠新建传统模式环境。查官方文档后确认存在更好的路。
- 事实链（CloudBase 官方文档）：
  - 创建环境时**选了 PostgreSQL** → 环境即以「PG 模式」运行（Postgres-Native，含 auth/storage/public 三 schema，权限走 GRANT + RLS，无安全规则）。
  - 「传统模式」（文档型数据库 + 安全规则）是旧模式；新控制台主推 PG 模式，所以建环境时只看到 PostgreSQL 选项是正常的，不是 bug。
  - **PG 模式可启用 `pgdoc` Document 插件**：接管文档型数据库 HTTP API（域名/路径完全不变），数据落 `pgdoc_data` schema，客户端 SDK 调用方式零改动。→ 这是本项目的正解，`utils/cb.js` 一行不用改。
- 启用方式：云开发控制台 → **Document 编辑器 → 启用 pgdoc**（纯控制台操作，无 API 凭证做不了）。启用后立即接管，不需重建、envId 不变、无数据迁移（本环境本来没文档库）。
- **代价/差异（必须先知道）**：`pgdoc` **只支持基础权限，不支持安全规则**。基础权限按 `_openid` 判定，四档：读取全部可改本人 / 读写本人 / 读取全部不可改 / 无权限。所以 `docs/cloudbase-setup.md` 里那两段安全规则 JSON 在 PG 模式**不适用**：
  - `attractions` → 选「读取全部数据，不可修改数据」，语义等价于原 `{read: auth!=null, write:false}`。
  - `marks` → 原设计用 `userKey`（设备维度）隔离，而基础权限按 `_openid` 判定；匿名登录下 `_openid` 是否填充未验证，**这是开完插件后必须实测的点**，可能需要把隔离改为 `_openid` 或把校验搬到云函数。
- 其他 pgdoc 限制：单文档 16MiB、单集合索引 ≤64、无跨请求游标、事务会话 10 秒、不支持 timeseries/clustered/change stream。对本项目无影响。
