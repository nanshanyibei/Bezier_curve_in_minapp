# 电子衣橱功能实施计划

## 一、目标与范围

在现有个人工作台小程序中新增「电子衣橱」：

- 以**底部第 5 个 Tab「衣橱」**作为入口（日记 / 旅行 / 衣橱 / 对话 / 我的）。
- 支持衣物**新增、查看、编辑、删除**，每件衣物含：照片（可选 1 张）、名称、分类、颜色、季节、备注。
- 支持**按分类、按季节筛选**，双列网格展示。
- 数据采用**本地 storage + 云端同步**：图片走云存储换 `fileID`，文档存 `wardrobe` 集合，按 `_openid` 隔离，冲突按 `updatedAt` 新者胜。
- 生产包（`dist/prod`）同样包含衣橱，因此需同步更新构建白名单。

不在本次范围：穿搭组合/OOTD、AI 推荐、收藏/常穿统计、多图相册。

### 2.2 关键约束

1. TabBar 最多 5 个，当前 4 个，正好可加 1 个。
2. Tab 页必须在主包，`pages/wardrobe/wardrobe` 不能放分包。
3. 客户端不能创建数据库集合，`wardrobe` 集合需在云开发控制台手动创建（权限「仅创建者可读写」）；未创建时同步静默降级本地，不阻断使用。
4. 生产包会剥离 `@dev:begin/@dev:end` 块，衣橱是正式功能，代码**不要**放进 dev 标记块；同时不得出现 `AI` / `siliconflow` / `deepseek` 等关键词（构建会失败）。

## 三、数据模型（决定项）

本地 storage key：`wardrobe.items`，结构 `{ v: 1, items: [...] }`。

```
entry = {
  id:        'w_<createdAt>_<rand5>',   // 一物一条，不能拿分类当 id
  name:      string,                    // 必填，≤40 字
  category:  'top'|'bottom'|'outer'|'shoes'|'accessory',
  color:     string,                    // 选填，≤20 字
  season:    'all'|'spring'|'summer'|'autumn'|'winter',
  note:      string,                    // 选填，≤500 字
  photo:     { fileID, local, w, h, failed } | null,
  createdAt: number,
  updatedAt: number,                    // 冲突按新者胜
  synced:    boolean                    // 仅本地字段，不上云
}
```

分类常量（`utils/wardrobeStore.js` 导出，页面与筛选共用）：

| key | label | emoji |
|---|---|---|
| top | 上装 | 👕 |
| bottom | 下装 | 👖 |
| outer | 外套 | 🧥 |
| shoes | 鞋包 | 👜 |
| accessory | 配饰 | 🧣 |

季节常量：`all 四季 / spring 春 / summer 夏 / autumn 秋 / winter 冬`。

云文档 `_id` 即 `entry.id`，字段为 `id/name/category/color/season/note/photo{fileID,w,h}/createdAt/updatedAt`（不写 `local/failed/synced`，与 `memoryStore.pushOne` 一致）。

## 四、改动清单

### 4.1 新增 `utils/wardrobeStore.js`

参照 `memoryStore.js`，导出：

- `KEY`、`NAME_MAX`、`COLOR_MAX`、`NOTE_MAX`、`CATEGORIES`、`SEASONS`
- `list()`：按 `createdAt` 倒序（同刻按 `updatedAt` 倒序）返回全部条目
- `get(id)`
- `save(entry)`：生成 id、置 `updatedAt=now`、`normalize`（名称必填；分类/季节非法时回落 `top`/`all`；照片统一清洗），本地落盘后异步 `pushOne`
- `remove(id)`：本地删除 + `cb.removeDoc('wardrobe', id)` + 删云存储图片 `cb.deleteFiles([fileID])`
- `stats()`：`{ total, byCategory: { top: n, ... } }`
- `pullCloud()`：`cb.listDocs('wardrobe')` → 按 `updatedAt` 新者胜合并；远端条目若与本地同 `fileID`，保留本地 `local` 路径，避免图片变灰块；返回 `{ items, changed }`
- `syncPending()`：补推 `synced=false` 的条目（启动时调用）

内部辅助：`loadAll/saveAll/rand/makeId/normalize/normalizePhoto/pushOne/patchLocal`。

### 4.2 新增页面 `pages/wardrobe/wardrobe`（Tab 页）

文件：`wardrobe.js / wardrobe.json / wardrobe.wxml / wardrobe.wxss`

- `wardrobe.json`：`navigationBarTitleText: "电子衣橱"`，`backgroundColorContent: "#16161c"`。
- `data`：`categories`、`seasons`、`filterCategory: 'all'`、`filterSeason: 'all'`、`items: []`、`stats: { total: 0, cats: 0 }`、`loading: true`。
- 生命周期：
  - `onLoad` → `render()`
  - `onShow` → 若已渲染过则 `render()`；并 `wardrobeStore.pullCloud()`，`changed` 时再 `render()`（与 diary 页一致）
- `render()`：取 `store.list()`，按当前分类/季节筛选；为每条计算 `display`（`photo.local`）、`emoji`、`categoryLabel`、`seasonLabel`、`seasonLabel`；`stats` 用 `store.stats()` 换算「共 N 件 · M 类」；`setData` 后调 `fillRemoteUrls()`。
- `fillRemoteUrls()`：收集 `display` 为空但有 `fileID` 的照片，`cb.getFileUrls` 批量换临时链接后回填。
- 交互：
  - 分类 chip 行：全部 + 5 个分类（横向滚动）
  - 季节 chip 行：全部 + 四季/春/夏/秋/冬
  - 双列网格：有图显示图片，无图显示分类 emoji 占位；卡片下方名称 + 「分类 · 季节」
  - 点击卡片 → `wx.navigateTo('/pages/wardrobe/edit/edit?id=' + id)`
  - 长按卡片 → `wx.showModal` 确认删除 → `store.remove(id)` → `render()`
  - 右下角悬浮「+」→ 新增
  - 空态：图标 + 「衣橱还空着」+ 「添加第一件」
- 样式只使用全局 CSS 变量与自有类，不改 `app.wxss`。

### 4.3 新增页面 `pages/wardrobe/edit/edit`

文件：`edit.js / edit.json / edit.wxml / edit.wxss`

- `edit.json`：`navigationBarTitleText: "添加衣物"`（`onLoad` 后按是否编辑改为「编辑衣物」）。
- `data`：`id`、`isEdit`、`name`、`category`、`color`、`season`、`note`、`noteCount`、`photo`（`{ local, fileID, display, uploading, failed } | null`）、`categories`、`seasons`、`saving`。
- `onLoad(options)`：有 `id` 时 `store.get(id)` 回填；照片 `display = local || ''`，仅 `fileID` 时调 `cb.getFileUrls([fileID])` 换链接。
- 表单：
  - 照片：单张，`wx.chooseMedia({count:1})` → `persistFile`（`copyFileSync` 到 `USER_DATA_PATH/wardrobe_*`）→ 压缩 → `cb.uploadImage`；替换时清理旧本地文件与旧 `fileID`；可删除、可预览、失败可重试（沿用 memory edit 的 `compressFile/unlinkQuiet/patchPhoto` 写法）。
  - 名称：`input`，`maxlength="{{nameMax}}"`（40）。
  - 分类：5 个 chip 单选。
  - 颜色：`input`，`maxlength="20"`，占位「如：米白 / 藏青」。
  - 季节：5 个 chip 单选（四季/春/夏/秋/冬）。
  - 备注：`textarea`，`maxlength="500"`，右下角计数。
- `onSave`：名称必填（去空格后为空则 toast「给衣物起个名字」）；调 `store.save({...})`；成功 toast 后 `setTimeout` `navigateBack`；保存中禁用按钮。
- `onDelete`（仅编辑态）：二次确认 → `store.remove(id)` + 清理本地图片 → 返回。
- 不做草稿机制（衣物表单短，保持简单）。

## 五、假设与决策

1. 每件衣物只存 **1 张封面图**，控制复杂度与流量；后续需要多图再加。
2. 分类固定 5 类，季节固定 5 值；不做自定义分类（避免额外管理界面）。
3. 名称必填、照片选填；无图时用分类 emoji 占位，保证列表可用。
4. 列表排序按创建时间倒序，新加的在前。
5. 删除衣物时同步删除云端文档与云存储图片；删除失败静默容忍孤儿文件（与回忆册一致）。
6. 衣物不做草稿；页面返回即丢弃未保存内容。
7. `wardrobe` 集合未创建时，所有云端调用按现有 `cb` 的失败降级逻辑走本地，不弹错误。
8. 衣橱属于正式功能，**不**使用 `@dev` 标记；生产包保留。
9. 不修改 `my` 页概览统计（日记/去过），避免超出本次范围。
