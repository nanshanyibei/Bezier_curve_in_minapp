# 衣橱照片「白底 + 去背景」实施计划（A + B + F）

## 一、目标

在电子衣橱的衣物照片上传前，增加**纯本地**的图片处理，不引入任何云端/AI 服务：

- **A 白底美化**：自动白平衡（边框取样、灰世界）、统一输出为白底方形图，主体居中留白。
- **B 简易去背景**：对纯色/近纯色背景做边缘泛洪抠图，背景替换为纯白；背景复杂时自动降级为 A，不阻断上传。
- **F 拍摄引导**：在编辑页给出「白墙/白纸平铺拍摄」「手机相册长按抠图后上传透明图」的使用提示。
- 用户可切换处理方式：**智能去背景 / 白底美化 / 原图**，选择记忆到本地。

不做：在线抠图 API、端侧 AI 模型、批量处理、背景编辑笔刷。

## 三、方案设计

### 3.1 新增 `utils/photoClean.js`（纯本地图像处理）

**导出**

```js
const MODES = { CUTOUT: 'cutout', WHITE: 'white', ORIGINAL: 'original' };

/**
 * @param {Object} opts
 * @param {string} opts.src        本地图片路径
 * @param {string} opts.mode       cutout | white | original
 * @param {Object} opts.workCanvas Canvas 2D 节点（像素处理用）
 * @param {Object} opts.outCanvas  Canvas 2D 节点（白底方图输出用）
 * @returns {Promise<{ path: string, applied: 'cutout'|'white'|'original', fallback: boolean }>}
 */
function processImage(opts) { ... }

module.exports = { MODES, processImage, whiteBalancePixels, cutoutMask };
```

`whiteBalancePixels`、`cutoutMask` 为纯函数（直接操作 `Uint8ClampedArray`），既供 `processImage` 使用，也便于用 Node 桩做验证。

**常量（决定项）**

| 常量 | 值 | 说明 |
|---|---|---|
| `WORK_MAX` | 900 | 工作画布最长边，控制 JS 像素运算耗时 |
| `OUT_SIZE` | 800 | 输出方形边长 |
| `MARGIN_RATIO` | 0.08 | 白边占边长比例 |
| `OUT_QUALITY` | 0.92 | 输出 JPG 质量 |
| 白平衡增益范围 | 0.85 ~ 1.20 | 防止过度偏色 |
| 泛洪色差阈值 | `clamp(d50 * 2.5 + 16, 24, 56)` | `d50` 为边框样本到中位色的距离中位数 |
| 抠图有效覆盖率 | 0.12 ~ 0.92 | 超出视为背景复杂，降级 A |

**处理流程**

1. `wx.getImageInfo(src)` 取尺寸与 `orientation`；通过 `canvas.createImage()` 加载图片。
2. 按最长边缩放到不超过 `WORK_MAX`，按 EXIF `orientation` 旋转/镜像（`up/down/left/right` 与 mirrored 变体），画到 `workCanvas`。
3. `getImageData` 取像素。
4. **白平衡（A）**：
   - 取图像四周 2px 环带样本（跳过 `alpha < 16`），逐通道排序求中位数。
   - 以三通道均值的平均值作为目标灰，计算每通道增益并限制在 `0.85 ~ 1.20`；逐像素应用。
   - 样本不足 100 个则跳过白平衡，避免小图误伤。
5. **去背景（B，仅 `cutout`）**：
   - 若边框样本多数透明（系统相册已抠好的 PNG），直接把 `alpha < 16` 的像素视为背景，不做泛洪。
   - 否则以边框像素为种子，按色差阈值做 4 邻域泛洪（`Uint8Array` 掩码 + `Int32Array` 栈），得到背景掩码。
   - 覆盖率 `< 0.12` 或 `> 0.92`、或边框同色样本占比 `< 0.6` → 判定失败，返回 `fallback: true`，按 A 输出。
   - 前景与背景交界的一圈像素按 45% 白混合，减轻锯齿。
6. **合成白底**：背景像素置纯白；半透明输入按 alpha 与白色混合；边缘像素叠加白混合。
7. `putImageData` 回 `workCanvas`，`wx.canvasToTempFilePath({ canvas: workCanvas, fileType: 'jpg', quality: OUT_QUALITY })` 导出。
8. 在 `outCanvas` 上铺 800×800 白底：`cutout` 用前景包围盒（向外留 4px）计算缩放，`white` 用整幅图，等比缩放到 `800 * (1 - 2 * MARGIN_RATIO)` 内并居中。
9. 再次 `canvasToTempFilePath` 导出最终 JPG，返回路径。

**失败策略**：`processImage` 内部任何一步异常都 reject；调用方捕获后按「原图 + 压缩」继续上传，并 toast 一次，绝不阻断保存。

### 3.2 改造 `pages/wardrobe/edit/edit.js`

**新增页面状态**

```js
data: {
  ...
  bgModes: [
    { key: 'cutout', label: '智能去背景' },
    { key: 'white', label: '白底美化' },
    { key: 'original', label: '原图' }
  ],
  bgMode: 'cutout',
  canvasOk: true,
  photo: null
  // photo = { orig, local, fileID, display, processing, uploading, failed }
}
```

- `bgMode` 从 `wx.getStorageSync('wardrobe.bgMode')` 读取，默认 `cutout`；切换时写回。
- `onReady` 用 `createSelectorQuery` 获取 `#workCanvas`、`#outCanvas`，存 `this._workCanvas / this._outCanvas`；获取失败置 `canvasOk: false`，隐藏处理选项并走原图上传。

**图片流程（替换现有 `addOne`）**

1. `onPickPhoto` → `chooseMedia` → `setPhotoFromTemp(tempPath)`。
2. `setPhotoFromTemp`：
   - `_photoToken++`；清理上一张的 `orig/local`；按真实扩展名（png/jpg/webp）`persistFile` 保存**原图**到 `USER_DATA_PATH/wardrobe_orig_*`。
   - `photo = { orig, local: '', display: orig, processing: true, uploading: false, failed: false }`。
   - 调 `runProcess(token)`。
3. `runProcess(token)`：
   - `bgMode === 'original'` 或 `!canvasOk` → `finalizeOriginal(token)`。
   - 否则 `photoClean.processImage({ src: orig, mode, workCanvas, outCanvas })` → 结果 `copyFile` 为 `wardrobe_*` 永久路径 → 更新 `local/display` → 删除被替换的旧 `local` → `uploadFinal(token, local, prevFileID)`。
   - 返回 `fallback` 时 toast「背景较复杂，已改用白底美化」。
   - 任意异常 → `finalizeOriginal(token)`，toast「处理失败，已改用原图」。
4. `finalizeOriginal(token)`：沿用现有 `compressFile`，压缩结果落永久路径，再 `uploadFinal`。
5. `uploadFinal`：`cb.uploadImage(local)` → 更新 `uploading/failed/fileID`；成功后删除上一版 `fileID`（避免换图遗留云文件）。
6. 所有异步回调先判断 `_photoToken === token`，保持现有防回写机制。

**交互**

- 照片字段下方新增处理方式 chips（复用 `.chip` 样式）；切换时若已有 `orig` 则用 `_photoToken++` 作废旧流程并重新处理，不再重新选图。
- `processing` 时照片角标显示「处理中」；`uploading` 显示「上传中」；`failed` 显示「重试」。
- `onSave` 增加拦截：`processing` 或 `uploading` 时 toast「图片处理中，请稍候」。
- `onRetryPhoto`：优先重传现有 `local`；`local` 丢失但有 `orig` 时重新走 `runProcess`。
- `onRemovePhoto` / 删除衣物：同时清理 `orig` 与 `local`（去重后 `unlinkQuiet`），并删除云 `fileID`。
- 编辑已有衣物时 `orig = local`（即已处理过的图）；切换处理方式会对已处理图再处理一次，属于已知限制。

## 四、假设与决策

1. 输出统一为 **800×800 白底 JPG**，主体留 8% 白边；与衣橱双列网格观感一致。
2. 默认处理方式为**智能去背景**，失败自动降级「白底美化」；选择记忆在 `wardrobe.bgMode`。
3. B 只面向纯色/近纯色背景；白衣服贴白墙、复杂花纹、毛发/针织边缘可能抠不干净，允许降级与手动切「原图」。
4. 透明 PNG 输入按 alpha 直接铺白底，适配手机相册「长按抠图」产物。
5. `orig` 原图只在本次编辑会话内保留，不写入 storage、不上云；用户保存后仅保留处理结果。
6. Canvas 节点获取失败（极老基础库/渲染异常）时，处理选项隐藏，沿用现有原图上传链路。
7. 所有处理在本地完成，无网络、无费用、无第三方数据流出；生产包可直接保留（不涉及 AI 关键词与类目）。
8. 性能目标：900px 工作图处理在常见机型 0.3~1.5s；超时或异常一律回退原图。

## 六、风险与边界

- **白底观感**依赖拍摄背景，F 的引导文案很关键；B 不是通用抠图。
- 泛洪基于颜色，深色/花背景会降级；不会破坏原图（原图始终保留到保存或删除）。
- Canvas 2D 逐像素处理在低端机上可能 1~2s，用处理中角标与保存拦截兜底。
- EXIF 方向处理需在 iOS/Android 各验证一次；异常时回退原图路径。
