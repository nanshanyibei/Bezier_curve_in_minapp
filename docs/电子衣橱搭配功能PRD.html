电子衣橱 · 搭配功能产品需求文档

在现有衣橱里选择上装、下装、鞋子，可再搭配包包与配饰，生成一张白底平铺搭配图并保存。

1. 背景与目标

现状：电子衣橱已经支持衣物拍照、白底处理、分类与季节筛选、增删改。每一件衣服是独立记录，用户只能逐件翻看。

问题：用户想判断「这件上衣配这条裤子、这双鞋，再加哪个包」时，只能靠想象或来回切换单件照片，看不到一套搭配的整体效果。

产品回应：在衣橱内增加「搭配」工作台。用户按位置选衣，系统按「上装在上、下装在中、鞋子在下、包与配饰在侧边」的固定版式，实时生成一张白底平铺搭配图；可以把搭配保存下来，下次直接查看。

期望结果（可观察）：用户不离开衣橱，就能完成「选几件衣服 → 看到整套搭配图 → 保存 → 在搭配列表再次打开」这一条完整路径。

假设：使用该功能的用户，衣橱中已分别录入至少 1 件上装、1 件下装、1 双鞋；否则进入新建搭配时需要先补齐衣物。

2. 范围

P0：本次必须完成

  • 分类调整：衣橱分类由「上装 / 下装 / 外套 / 鞋包 / 配饰」调整为「上装 / 下装 / 外套 / 鞋 / 包 / 配饰」，让鞋子与包可以分别选择。
  • 双模式入口：衣橱页顶部可在「衣物 / 搭配」之间切换。
  • 新建搭配：选择上装（或外套）、下装、鞋；可选 1 个包、最多 2 件配饰；实时预览白底拼图。
  • 保存搭配：命名并保存搭配图与衣物清单；本地可用，联网后同步云端。
  • 搭配列表与详情：查看已保存搭配的大图与衣物清单，支持删除。
  • 空态与异常：分类缺衣、生成失败、上传失败、网络断开时都有明确反馈与恢复路径。

P1：后续增强

  • 重新编辑已保存的搭配（换一件衣服再保存）。
  • 把搭配图保存到手机相册。
  • 在选衣时按季节过滤候选衣物。

不包含

  • 真人试穿、衣服贴合身体的上身效果。
  • 自动推荐、随机搭配、根据天气推荐。
  • 分享给好友、多人协作、搭配社区。

3. 核心概念与规则

搭配：一组被选中的衣物，加上按固定版式生成的一张搭配图。搭配是衣物的「快照」：保存后即使原衣物被删除或修改，已保存的搭配图与清单仍然保留。

3.1 槽位定义

槽位可放入的分类数量是否必选说明
上装上装、外套1必选上装与外套二选一，不能同时选两件
下装下装1必选裤子、裙子等统一归入下装
鞋鞋1必选放在画面最下方
包包0~1可选放在右侧辅列上方
配饰配饰0~2可选放在右侧辅列下方，最多两件

3.2 关键规则

  • 不可重复占用：同一件衣物在同一套搭配中只能出现一次；上装槽与外套槽位合并为上装槽。
  • 必选校验：上装、下装、鞋未选齐时不能保存，保存按钮置灰，并提示缺少的槽位。
  • 数量上限：包最多 1 个，配饰最多 2 件；超出时提示「最多搭配 X 件」。
  • 实时预览：每次选择变化后重新生成预览；预览图就是最终保存图，所见即所得。
  • 搭配图规格：正方形、纯白背景、输出为 JPG；主体等比缩放，不拉伸、不裁剪。
  • 空槽不占位：没有选择包或配饰时，右侧辅列不显示，主列自动居中并适当放大。
  • 快照规则：保存时记录衣物名称、分类与当时的搭配图；后续衣物被删除，搭配图仍可查看，清单中标记「已删除」。
  • 命名规则：名称选填，最多 20 个字；不填写时自动使用「搭配 M月D日 HH:mm」。

4. 搭配图布局

整体为 1:1 白底画布，默认留白 5%~6%。主列占宽约 56%，右侧辅列占宽约 22%~20%。

  • 主列：上装 → 下装 → 鞋，从上到下垂直排列；上装与下装各占约 27%/26% 高度。
  • 鞋区：占宽约 38%、高约 12%，明显小于上装与下装，位于画面下方。
  • 辅列：包约 22%×18%，配饰每件约 20%×16%，整体面积小于主列衣物。
  • 可选槽为空：辅列隐藏，主列水平居中，衣物展示框宽度适当放大。
  • 图片适配：每类使用固定展示框，先裁掉照片白边再等比缩放居中放入；不裁切主体、不拉伸。
  • 占位：衣物没有照片时，在该位置显示浅灰圆角块与分类文字，不显示衣物名。

5. 功能需求

FR-01 分类调整与存量迁移 P0

目的：让鞋子和包可以分别被选择，避免「鞋包」一个分类无法区分槽位。

  • 衣橱分类改为 6 类：上装、下装、外套、鞋、包、配饰。
  • 衣物列表的筛选条、衣物编辑页的分类选项同步改为 6 类。
  • 存量迁移：原「鞋包」分类下的衣物默认归入「鞋」；用户可在衣物编辑页改为「包」。
  • 迁移不改变衣物名称、照片、颜色、季节、备注等已有信息。
已确认：按上述方案拆分分类，存量「鞋包」衣物归入「鞋」，用户可在衣物编辑页改为「包」。

FR-02 衣橱双模式入口 P0

目的：不增加底部 Tab，在衣橱内直接进入搭配。

  • 布局：衣橱页顶部、统计信息下方增加分段切换「衣物 / 搭配」。
  • 默认状态：首次进入停留在「衣物」；记住用户上次选择，下次进入时回到上次模式。
  • 衣物模式：保持现有分类/季节筛选、双列网格与添加按钮。
  • 搭配模式：展示已保存搭配的双列网格；右下角悬浮按钮变为「+ 新建搭配」。
  • 空态：还没有搭配时，显示「还没有搭配」与「新建第一套」按钮。

FR-03 新建搭配 P0

目的：完成「选衣 → 看到整体效果」的核心动作。

页面结构（从上到下）：

  1. 搭配预览：正方形白底预览区，实时显示当前选择生成的搭配图。
  2. 上装：候选衣物横向列表，包含上装与外套，单选。
  3. 下装：候选衣物横向列表，单选。
  4. 鞋：候选衣物横向列表，单选。
  5. 包：候选衣物横向列表，最多选 1 件。
  6. 配饰：候选衣物横向列表，最多选 2 件。
  7. 底部：「保存搭配」按钮。

选择规则：

  • 点击未选中的衣物即选中；再次点击已选中的衣物即取消。
  • 必选槽位切换选择时，旧选择自动取消，不需要先取消再选。
  • 配饰超过 2 件、包超过 1 件时，不改变当前选择，并提示数量上限。
  • 候选衣物按最近添加时间倒序，展示缩略图与名称；没有照片的衣物显示分类图标占位。
  • 某个槽位没有任何候选衣物时，显示「这个分类还没有衣物」与「去添加」，点击进入新增衣物页并默认选中该分类。

预览规则：

  • 必选槽位未选齐时，预览区对应位置显示虚线占位与分类名。
  • 选择变化后立即刷新预览；生成过程中显示「生成中」，不阻塞继续选衣。
  • 生成失败时保留当前选择，显示「预览生成失败，点击重试」，可重试。

FR-04 保存搭配 P0

  • 触发：点击「保存搭配」。必选槽位未齐、预览未生成完成、正在保存时按钮不可用，并给出原因提示。
  • 命名：弹出命名框，预填「搭配 M月D日 HH:mm」，最多 20 个字，可留空使用预填名称。
  • 保存内容：搭配名称、搭配图、所选衣物清单（衣物名称与分类快照）、创建时间。
  • 结果：保存成功后提示「已保存」，返回搭配列表，新搭配排在最前面。
  • 失败：搭配图生成失败不允许保存；本地保存成功但云端同步失败时，仍视为保存成功，并标记为待同步，不打断用户。
  • 防重复：保存过程中按钮显示「保存中」，重复点击不产生第二条记录。

FR-05 搭配列表与详情 P0

  • 列表：双列卡片，展示搭配图、名称与创建时间，按创建时间倒序。
  • 详情：点击卡片进入详情，展示大图、名称、创建时间、衣物清单（分类标签 + 衣物名称）。
  • 已删除衣物：清单中对应衣物显示删除线或「已删除」标签，搭配图不受影响。
  • 删除：详情页提供删除，二次确认后删除本地与云端的这条搭配；不删除任何衣物。
  • 返回：从详情返回列表时，列表保持当前滚动位置。

P1：重新编辑、保存图片到相册。

FR-06 同步与恢复 P0

  • 搭配与衣物一样：本地优先，联网后自动同步云端。
  • 换设备或重装后，登录同一微信账号可以拉回已保存的搭配图与清单。
  • 同一套搭配在两台设备上被修改时，以最近保存的版本为准。
  • 离线时仍可创建、查看、删除搭配；联网后自动补同步。

7. 共享规则

7.1 分类与槽位对应

衣物分类可进入的槽位
上装上装槽
外套上装槽（与上装二选一）
下装下装槽
鞋鞋槽
包包槽
配饰配饰槽

7.2 图片展示

  • 搭配图固定 1:1、纯白底；上传前已做过白底处理的衣物图直接使用。
  • 每个槽位有固定展示框，衣物图等比放入并居中；上装与下装优先展示完整轮廓。
  • 没有照片的衣物用分类图标占位，不阻断搭配与保存。
  • 搭配图生成后即为最终保存图；后续更换衣物照片不会自动更新旧搭配。

7.3 编辑与删除边界

  • 删除衣物不影响已保存搭配与搭配图。
  • 删除搭配只删除这条搭配，不影响衣物。
  • P0 不支持修改已保存搭配的衣物；需要调整时新建一套。

7.4 权限与隐私

  • 搭配数据仅本人可见、可操作，不提供分享与公开入口。
  • 搭配图在手机本地生成，不把衣物照片发送给第三方服务。
  • 开启云端同步后，搭配图与清单保存在本人的私有云空间；删除搭配时同步清理云端数据。
