# MRD：今天吃什么 · 家常菜随机选

> 版本 v1.0 · 2026-11-25 · 作者：南山
> 关联现状：tabBar 5 个已满，需找入口位置；现有 pages 结构、assets/data 本地数据模块（CommonJS require/module.exports）、CloudBase 同步模式

---

## 0. 背景与目标

**痛点**：每周到做饭时刻，面对「今天吃什么」这个宇宙难题陷入决策瘫痪，最终要么点外卖要么重复上周那几道菜。

**目标**：在现有小程序里挂一个「今天吃什么」功能，预置一份家常菜数据（按菜系/做法分类），核心就是**一键随机抽一道菜**，辅以收藏、历史、自定义扩展三个增强能力。

**设计原则**：
- **纯本地优先**：菜品数据本地 JS 模块，不需要联网就能跑；云端同步作为可选增强
- **零 AI 依赖**：prod 构建不受 AI 剥离规则影响（`scripts/build.js` 白名单追加即可）
- **入口轻量**：不挤 tabBar（已 5 个），用首页入口卡片 + 「我的」页模块双入口
- **视觉克制**：延续现有深色主题（`#16161c` 背景、`#6ea8fe` 主色），菜品图用 `text_to_image` API 生成占位（MVP 接受，后续可替换为真实图）

**成功指标（个人工具口径）**：
- 3 秒内完成「打开 → 随机抽中 → 看到菜品名+图」全链路
- 预置菜品 ≥ 80 道，覆盖主流菜系与做法
- 杀进程重开，收藏/历史/自定义数据保留

## 2. 功能详细设计

### 2.1 入口位置

tabBar 已满 5 个，新增 tab 需挤掉一个且体验不好。采用双入口：

1. **「我的」页模块入口**（主入口）：`pages/my/my.wxml` 现有 grid/list 区域插入一个「今天吃什么」卡片，图标用 food 类 SVG 或生成图
2. **日记页顶部浮动入口**（快捷入口，可选）：日记 tab 首屏 top 区域插一个轻量卡片「今天吃什么 →」

两入口均跳转同一个页面 `pages/food/food`。

### 2.2 主页面：随机抽菜（P0）

#### 用户故事

- US1：作为用户，我点页面中间大按钮，快速切换若干菜品卡片（2-3 秒动效），最终停在一道菜上，解决决策困难。
- US2：作为用户，同一道菜被抽中后可以换，也可以点「就它了」接受结果。
- US3：作为用户，抽菜过程不要卡顿，动效要顺滑有节奏感。

#### 交互设计

```
┌─────────────────────────────────┐
│  今天吃什么？                     │
│  ─────────────────────────────── │
│                                  │
│  ┌─────────────────────────┐     │
│  │                         │     │
│  │     菜品卡片区域         │     │
│  │    （图 + 菜名）         │     │
│  │                         │     │
│  └─────────────────────────┘     │
│                                  │
│  [ 🔀 随机抽菜 ]   [就它了 ✓]   │
│                                  │
│  筛选: [全部] [川菜] [粤菜] ...   │
│                                  │
│  历史 [30]  收藏 [12]  我的菜 [5]│
└─────────────────────────────────┘
```

**抽菜动效**（参考经验 #1465686 成功方案）：
- **先固定最终 randomIndex**（均匀分布，一次随机决定）
- **动画阶段**（1.5-2 秒）：setTimeout 快速切换临时菜品显示，制造"洗牌"效果
- **动画结束**：回填预先确定的最终菜品，保证随机公平性

#### 功能需求

| # | 需求 | 优先级 | 说明 |
|---|---|---|---|
| FR1 | 大按钮触发随机抽菜，有快速切换动效 | P0 | 动效 ≥ 1.5s，≤ 3s |
| FR2 | 每次抽菜从当前筛选池均匀随机 | P0 | `Math.floor(Math.random() * pool.length)` |
| FR3 | 结果可换（再次点随机）、可接受（"就它了"） | P0 | 接受 = 写入历史 |
| FR4 | 筛选：按菜系标签过滤菜品池 | P0 | 标签见 3.1 |
| FR5 | 空池提示（筛选后 0 道） | P0 | toast「该分类暂无菜品，换一个试试」 |

### 2.4 收藏、历史、自定义（P1）

**收藏**：`pages/food/food` 底部 tab 区域或弹层入口 → 收藏列表页，展示已收藏菜品卡片网格；可取消收藏。

**历史**：最近 30 次抽取结果（含"换"的中间结果，只保留最终选中的）。超过 30 条自动丢弃最早的。

**自定义添加**：`pages/food/food` 页或「我的」页入口 → 添加表单：
- 菜名（必填）
- 分类标签（选一个或多个，下拉/多选）
- 难度/耗时（可选，填了更好）
- 简要用料 + 做法（可选）
- 图片（可选：不上传则生成占位图；MVP 阶段不支持用户拍照上传，保持本地）

自定义菜品存入本地数据池，和预置菜品一起参与随机抽选。

### 2.5 云端同步（P2）

沿用项目现有 CloudBase 同步模式：
- 新集合 `food_favorites`（收藏）和 `food_custom`（自定义菜品）
- 每类数据整条文档，`updatedAt` 新者胜（与 travel.routes 同策略）
- 可选开关：在「我的」页数据管理里暴露同步开关，默认关闭（个人工具，节省云资源）

## 5. 技术方案要点

### 5.1 抽菜核心逻辑

```js
// utils/foodStore.js 伪代码
function randomPick(tags = []) {
  const pool = getDishesByTags(tags);
  if (pool.length === 0) return null;

  // 先固定结果（均匀随机）
  const finalIndex = Math.floor(Math.random() * pool.length);
  const finalDish = pool[finalIndex];

  // 返回给 UI 层：先展示 finalDish，动画期间 UI 自己快速换临时菜品
  return finalDish;
}
```

UI 层（food.js）：
```js
onRandomTap() {
  const final = foodStore.randomPick(this.data.filterTags);
  if (!final) { wx.showToast({ title: '该分类暂无菜品', icon: 'none' }); return; }

  this.setData({ picking: true });
  // 动画：200ms 一次换临时菜品
  let i = 0;
  this._timer = setInterval(() => {
    const temp = this.data.pool[Math.floor(Math.random() * this.data.pool.length)];
    this.setData({ current: temp });
    if (++i >= 10) {          // ~2s 后停
      clearInterval(this._timer);
      this.setData({ current: final, picking: false });
    }
  }, 200);
}

onAccept() {
  foodStore.pushHistory(this.data.current.id);
  wx.showToast({ title: '就它了 ✓', icon: 'none' });
}
```

## 7. 验收要点

- **抽菜**：连续抽 20 次，无报错、动效流畅、最终菜品不重复率 ≥ 80%（样本均匀分布近似）
- **筛选**：每个 tag 组合都能返回正确结果；空筛选（全部）覆盖所有预置菜 + 自定义菜
- **收藏**：收藏后退出重进仍在；取消收藏即时生效；详情页与列表页状态一致
- **历史**：≥ 30 条时最早自动丢弃；按时间倒序显示
- **自定义**：添加后立即进入随机池；可删除；删除预置菜（不应允许）有保护
- **数据持久化**：杀进程重开，以上数据全部保留

## 9. 非目标（明确不做）

- ❌ 不接入美团/饿了么 API（点餐、外卖）—— 我们只负责"选什么菜自己做"
- ❌ 不做食材价格查询、超市比价
- ❌ 不做复杂推荐算法（基于历史偏好、季节食材等）—— 保持均匀随机的纯粹感
- ❌ 不做多人"投票选菜" —— 单人工具定位
- ❌ 不做视频/图文教程跳转（外部链接会受小程序白名单限制），做法写死在本地即可
- ❌ 不做 tabBar 新增（要挤掉现有 tab 会影响已有功能入口）
