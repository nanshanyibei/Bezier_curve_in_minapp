# MRD：路线绘制 & 景点打卡定位

> 版本 v1.0 · 2026-11-13 · 作者：南山 × WorkBuddy
> 关联现状：pages/travel（canvas 地图 + 下钻）、utils/travelStore（marks v3）、utils/geoRender、utils/geoGesture、utils/cb（CloudBase 同步）

---

## 0. 背景与目标

当前足迹地图只回答「我去过哪 / 想去哪」，缺少两个自然延伸：

| 功能 | 回答的问题 | 目标 |
|---|---|---|
| 路线绘制 | 「怎么串起来 / 接下来怎么走」 | 把去过/想去的城市连成可命名的路线，地图上可视化 |
| 打卡定位 | 「我现在真的在哪」 | 到达某地后一键打卡，自动定位到对应行政区划并标记 visited |

共同目标：不引入任何 AI 依赖（**prod 环境可上**），纯本地优先 + CloudBase 同步，沿用现有「storage 即时落盘 + 异步推云 + pullCloud 新者胜合并」模式。

成功指标（个人工具口径）：
- 打卡成功率（定位→正确 adcode）≥ 95%
- 路线创建 3 步内完成（起名 → 点选城市 → 保存）
- 首屏地图渲染耗时增加 ≤ 50ms（含路线）

## 1. 功能一：路线绘制

### 1.1 用户故事

- US1：作为用户，我想把「想去」的几个城市按顺序连成一条路线，在地图上看到一条规划线，感受行程节奏。
- US2：作为用户，我想给路线起名（如「川西环线 2027 春」），并区分「规划中 / 已走完」两种状态。
- US3：作为用户，走过的城市在路线上自动变实心，一眼看出完成度。
- US4：作为用户，我想调整路线里城市的顺序（增删、拖动排序）。
- US5：作为用户，我想看到路线的概要信息：城市数、直线总里程（Haversine）。

### 1.2 交互设计

**入口**：地图页右上工具区新增「路线」按钮 → 底部弹层（复用现有 sheet 风格）：
- 路线列表：名称 + 城市数 + 状态徽标（规划/完成）+ 完成度小进度条
- 「+ 新建路线」

**创建流程（3 步）**：
1. 弹层输入名称（默认「路线 YYYY-MM-DD」，可改）
2. 进入「选点模式」：地图回到全国视图，顶部提示「依次点选城市（≥2 个），已选 n 个」；点击有标记的行政区（visited 或 want 均可）即加入路线尾部，再点一次移除；已选城市按顺序编号标注 ①②③
3. 点「完成」→ 保存并返回，地图绘制该路线

**地图渲染**：
- 路线节点 = 城市中心点 `marks[adcode].center`（已在数据里）
- 节点间连线用**二次贝塞尔曲线**（控制点取两节点中垂线偏移，偏移量与节点距成比例），呼应项目主题；相邻路线段控制点同侧偏移避免交叉重叠
- 「规划中」= 虚线（want 色系）；「已完成」= 实线（visited 色系）；段的颜色跟随该段两端城市的实际标记状态（端点去过→实线）
- 节点小圆点 + 序号；该路线处于「展示中」时其他路线淡化（alpha 0.3）
- 多条路线可同时展示，弹层里每条路线带显隐开关

**编辑**：路线详情弹层 → 重命名 / 重新选点（进入选点模式，保留原顺序可增删）/ 调序（列表页上下移）/ 删除（二次确认）/ 状态切换（规划 ↔ 完成）

### 1.3 功能需求

| # | 需求 | 优先级 | 说明 |
|---|---|---|---|
| FR1-1 | 创建路线（名称+有序城市列表） | P0 | ≥2 城市才可保存 |
| FR1-2 | 地图绘制贝塞尔路线 + 序号节点 | P0 | 复用 geoRender 投影，随缩放/平移重绘 |
| FR1-3 | 路线列表弹层 + 显隐开关 | P0 | |
| FR1-4 | 编辑：增删城市、列表调序、重命名 | P1 | 调序 MVP 用上移/下移按钮，不做拖拽 |
| FR1-5 | 状态切换（规划/完成）+ 分段变色 | P1 | 「完成」= 所有节点城市均 visited 时自动提示一键切换 |
| FR1-6 | 直线总里程估算（Haversine） | P1 | 显示在详情弹层，标注「直线距离，仅供参考」 |
| FR1-7 | 路线云端同步 | P1 | 新集合 `routes`，整文档 updatedAt 新者胜（文档级，不做条目级） |
| FR1-8 | 「想去」城市一键串联建议 | P2 | 按就近贪心排序生成初稿，用户可再调。纯本地几何计算，无 AI |

**非目标**：不做真实导航/路网路径规划（只画城市间直线-贝塞尔示意）；不做多路线交汇避免计算；不做交通方式/时间。

### 1.4 数据模型

本地 storage key `travel.routes`：

```js
{
  v: 1,
  routes: [{
    id: 'r1699...',          // Date.now() + 随机后缀
    name: '川西环线 2027 春',
    status: 'plan',          // 'plan' | 'done'
    adcodes: ['510000', '513300', '513400'],  // 有序
    hidden: false,           // 地图显隐（本地态，不上云）
    createdAt: 1699...,
    updatedAt: 1699...
  }],
  updatedAt: 1699...
}
```

云端（CloudBase，新集合 `routes`，沿用 userKey 隔离）：整条路线一个文档，字段同上（去掉 hidden），`updatedAt` 文档级新者胜。`utils/cb.js` 新增 `pushRoute` / `fetchRoutes`。

### 1.5 技术方案要点

- 新增 `utils/routeStore.js`：API 对齐 travelStore（getAll/get/upsert/remove/pullCloud），含 migrate 兜底
- 新增 `utils/geoRoute.js`：纯函数模块（可单测）
  - `buildPath(points, offset)` → 贝塞尔控制点序列
  - `haversine(a, b)` 里程
- 渲染进 `geoRender`：新增路线图层（在行政区填充层之上、景点标注之下）；`_animToken` 机制沿用，缩放/平移手势后随 draw() 重绘
- 命中检测：选点模式复用现有行政区点击链路（geoGesture 已有点→行政区判定）
- **构建**：`scripts/build.js` 白名单需追加新文件（geoRoute/routeStore 等如有独立文件）；两功能均无 AI 关键词，不受 `@dev` 剥离影响

## 2. 功能二：景点/城市打卡定位

### 2.1 用户故事

- US1：作为用户，我人到了某个城市，打开小程序点「打卡」，自动识别我所在的市/区，把地图上该区域标记为 visited，无需手动翻列表。
- US2：作为用户，打卡成功后有即时反馈（动画 + 该区划高亮 + 覆盖率刷新）。
- US3：作为用户，定位识别不到（境外/数据未覆盖）时，我能手动选择正确区划完成打卡。
- US4：作为用户，我想看到每个城市的打卡记录（时间），在足迹清单里能看到「某年某月到达」。

### 2.2 交互设计

**入口**：地图页右上「打卡」按钮（或省级视图 sheet 内新增「我在这里打卡」）。点击 →
1. 请求定位（见 2.5 权限）→ 拿到经纬度
2. **离线点判定**：用当前已加载的行政区划 geojson 做 point-in-polygon，从区级逐级向上匹配，得到 `adcode`
3. 命中 → 确认弹层：「检测到你在 杭州（330100），标记为去过？」→ 确认后 set 标记 + `confirmedAt`，地图高亮 + 短暂缩放动画
4. 未命中（境外、海域、边界数据缺口）→ 提示并提供手动选择（跳转 subpackages/geo 的 place 选择页回来兜底）

**打卡记录**：travelStore marks 每条新增 `confirmedAt`（时间戳，null=手动标记未打卡）；清单页条目右上角显示「📍 YYYY.MM.DD 打卡」徽标；「我的」页数据概览新增「打卡城市数」。

### 2.3 功能需求

| # | 需求 | 优先级 | 说明 |
|---|---|---|---|
| FR2-1 | 一键打卡：定位→区划判定→确认→标记 visited | P0 | 主链路 |
| FR2-2 | 离线 point-in-polygon 判定（区→市→省逐级） | P0 | 不依赖任何逆地理编码 API，零成本 |
| FR2-3 | 打卡时间记录 confirmedAt + 清单徽标 | P0 | |
| FR2-4 | 未命中兜底：手动选区划打卡 | P0 | 复用 place 选择页 |
| FR2-5 | 打卡成功动效（高亮 + 覆盖率数字滚动） | P1 | 纯 canvas/CSS |
| FR2-6 | 打卡历史列表（我的页） | P2 | 按 confirmedAt 倒序 |
| FR2-7 | 打卡联动路线：打卡命中某路线节点时提示完成度 | P2 | 「该路线 3/5 已完成」 |

**非目标**：不做防作弊校验（个人自用，信任 GPS）；不做持续后台定位/轨迹记录（耗电且隐私敏感）；不做景点级 GPS 打卡（MVP 只到区县级）。

### 2.4 数据模型

`travel.marks` **v3 → v4 迁移**（travelStore.migrate 扩展，向后兼容）：

```js
marks[adcode] = {
  status, name, center,
  confirmedAt: 1699... | null,  // 新增：打卡确认时间
  updatedAt
}
```

云端 marks 文档同步加 `confirmedAt` 字段（pushMark/pullCloud 透传，新者胜逻辑不变，无需新集合）。

### 2.5 权限与合规（关键风险）

**R1（高危）：`wx.getLocation` 类目限制。**
2022 年起 `wx.getLocation` 为受限隐私接口，需在 mp 后台申请开通，且开放类目有限（出行/物流等），**个人主体大概率批不下来**。对策分层：

| 方案 | 接口 | 个人主体可行性 | 精度 |
|---|---|---|---|
| A | `wx.getLocation` | 低（需类目审批） | 精确 |
| B | `wx.getFuzzyLocation` | 需声明 requiredPrivateInfos，审批口径稍宽，先试这个 | 模糊（~1km，对区县级判定完全够用） |
| C | 手动兜底 | 100% | 无定位，用户自选区划 |

**实施顺序：B → 不通则 C。** 若 B 也被拒，功能降级为「手动打卡 + 确认动效」，FR2-1/2-2 保留为 dev 环境能力（`@dev` 标记包裹），prod 上线手动版。

**其他合规项**：
- `app.json` 需加：`"requiredPrivateInfos": ["getFuzzyLocation"]` + `permission.scope.userFuzzyLocation.desc`
- 隐私指引页（pages/my/privacy）补「位置信息」用途说明；privacy 接口弹窗微信侧自动管
- 定位失败/拒绝授权：引导到设置页 `wx.openSetting`，且有手动兜底，不阻断

### 2.6 技术方案要点

- 新增 `utils/geoLocate.js`：
  - `fuzzyLocate()` → Promise<{lon,lat}>（封装 getFuzzyLocation，失败返回 errCode）
  - `pointInRegion(lon, lat, polygons)` → boolean（射线法，geoSimplify 已有简化几何可复用；数据加载策略沿用现有按需下载/缓存）
  - `locateAdcode(lon, lat, ctx)` → 自上而下：先省后市逐级 polygon 匹配（全国 34 省 polygon 常驻内存可行，市级按需）
- 打卡动作写 travelStore（新增 `checkin(adcode)` 封装：set + confirmedAt + 推云）
- 地图页 `onShow` 恢复时已有重绘链路，打卡动效挂 `_animToken` 同一套

## 3. 里程碑

| 阶段 | 内容 | 产出 |
|---|---|---|
| M1 | routeStore + geoRoute + 创建/列表弹层 + 地图绘制（FR1-1~3） | 路线 MVP |
| M2 | geoLocate + 打卡主链路 + v4 迁移 + 清单徽标（FR2-1~4） | 打卡 MVP（先手动兜底保底可用） |
| M3 | 路线编辑/调序/里程 + getFuzzyLocation 提审 + 动效（FR1-4~6, FR2-5） | 完整版 |
| M4 | 云端同步（routes 集合 + confirmedAt 透传）+ P2 项 | 收尾 |

依赖关系：M2 的手动兜底不依赖任何审批，可先行；B 方案审批并行走。

## 4. 验收要点（摘要）

- 路线：≥2 点可存；单点/0 点不可存并提示；缩放平移后曲线跟随；删除路线地图即消失；杀进程重开数据在
- 打卡：模拟器 mock 坐标命中正确市/区；境外坐标走手动兜底；拒绝授权可从设置页返回重试；prod 构建产物 grep 无 AI 关键词、构建不失败
- 数据：v3 老数据升级后 marks 原样保留；云端与本地双写各自 updatedAt 不互踩

## 5. 风险清单

| 风险 | 等级 | 对策 |
|---|---|---|
| getFuzzyLocation 审批被拒 | 高 | 手动兜底保底；精确定位永久放弃，不阻塞上线 |
| 市级 geojson 未下载时打卡判定慢/缺数据 | 中 | 打卡前检查已缓存区划，未缓存则先加载（现有 loading/progress 机制复用） |
| 贝塞尔控制点在路线回折（如 A→B→A）时穿帮 | 中 | 控制点偏移量加下限，回折段加大曲率；渲染效果 M1 内调 |
| routes 云端合并为文档级，双设备同时编辑丢改动 | 低 | 个人工具可接受；文档里 updatedAt 覆盖前可备份到 storage 历史槽位（P2） |
